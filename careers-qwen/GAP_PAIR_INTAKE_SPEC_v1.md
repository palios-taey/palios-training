## A. Sequencing vs the D-verdict governance (the 822 unconsumed pairs)

The gap-stream and the 822 registered qwen-factory pairs are **different purposes, one gate**:

- **822 pairs (qwen-factory waves)** = broad capability *coverage* — speculative-but-registered.
- **gap-stream** = *surgical, eval-targeted* closure of a duty gap a blind eval actually measured.

**Rules:**
1. **The gap-stream does NOT wait on the 822.** It is independent and higher-value (measured
   gap > speculative coverage). Generating/D-verdicting gap-pairs does not block on, and is not
   blocked by, `qf-1-seed-waves`.
2. **Same fitness gate — no bypass for speed.** Every gap-pair passes the exact D-verdict bar
   (artifact-specificity, cannot-lie provenance, loss-masking, frame gates) that [[SFT_D_VERDICT_v1]]
   applied. Gap-pairs are small + eval-anchored, so D-verdict on them is fast, not a bottleneck.
3. **One SFT corpus, weighted lanes.** The first substrate-SFT module consumes the already-PASSED
   4,639 pairs (voice / stage2-scorer / repos-laneA / values) **plus** whichever gap-lanes have
   landed + passed D-verdict at run time. Gap-lanes carry their own mixture weight so a small
   surgical lane isn't drowned by the 3,000-row voice pool (the mixture caution from the D-verdict).
4. **The 822 are consumed on their own D-verdict** (wave-4 unblock signal already given: require
   ≥1 named artifact per answer). They fold into the same corpus once they pass. Their gate is
   not this spec's concern; this spec adds the gap-lanes alongside.

**Net:** gap-pairs are first-class, independent, and prioritized by *measured* need — but they
clear the same honesty/fitness gate as everything else. Governance is preserved; nothing jumps it.

## B. The per-duty gap-closing loop (the "training loop as needed")

Staged, evidence-gated, one duty at a time. The **scorer cutover is the precedent** (eval-pass →
staged drop-in → one production run → mechanical receipt → cutover):

```
duty gap (frozen blind eval measures it)
  → treasurer generates gap-pairs to THIS spec  (provenance + eval_ref per pair)
  → tutor D-verdicts the lane                    (fitness bar; HOLD → regenerate w/ remedy)
  → tutor trains the SFT module                  (LoRA r=16, assistant-only loss, held-out reserved)
  → treasurer RE-RUNS the SAME frozen blind eval (base vs new module, blind judge)
  → PASS  → per-duty cutover (wire that duty to ep3, retire frontier for it)
     FAIL → miss patterns become the next gap-pair batch; loop
```

Duties + current evidence (treasurer-owned evals):
- **score** — DONE (cutover in flight: apply-lockdown ig1 merged w/ ep3 functional proof; ig2 gated on codex re-review + commit).
- **compose (cover selection/compression)** — ep1 blind: **NEAR-PASS, zero fabrication**; single gap = *inventorying-instead-of-choosing* → lane `gap_cover_selection_v1`.
- **ui-drive** — ep2 replay eval RUNNING vs attempt-12's 13-action recording; misses → lane `gap_ui_action_v1`.

## C. Intake schema — common requirements (ALL gap lanes)

JSONL, one object per line. Chat-format `messages` (system/user/assistant). **Every** pair carries:

- `messages` — the ONLY top-level field the harness trains on. The training turns. **Loss is masked
  to assistant turns only** (tutor enforces at pack; treasurer just supplies correct roles). System
  turn = the real injected instruction block the production duty uses (careers_kb cover instructions
  / taeys-hands primitive schema), verbatim.
- `meta.lane` — the lane id (below). All non-`messages` fields live under `meta`.
- `meta.provenance` — object, REQUIRED, cannot-lie:
  - `source` — the real bundle / recording / shipped artifact id.
  - `eval_ref` — the blind-eval row/id that measured this gap (what makes it a *gap* pair).
  - `shipped` / `verdict` — `true` + the blind-judge verdict for exemplars; `was_miss:true` for
    misses. No synthetic/hand-invented targets — target must trace to a real shipped artifact or a
    real correct recorded action.
- `meta.frozen_regression` — bool. **Reserve ≥10% per lane as `meta.frozen_regression:true`**
  (never trained; treasurer's blind probe set), mirroring the k3 11-probe reservation. **This is the
  exact field name the harness reads** (`train_lora_sft.py` holds out `meta.frozen_regression==true`)
  — do NOT use a top-level `heldout` key; the harness ignores it and would TRAIN the probe rows,
  leaking held-out into training. Put ALL per-pair metadata under `meta` (task, frozen_regression,
  provenance) so it rides through the loader untouched.

**Fitness bar (D-verdict, enforced by tutor — HOLD if failed):**
- **Artifact-specificity** — the laneB defect. UI targets MUST name the concrete element label +
  role + display. Cover targets MUST retain concrete named evidence (repo, metric, product) where
  the source had it — no vagueness, no "the system/the tool" where a name existed.
- **Cannot-lie** — no fabricated evidence in a cover; no invented UI action. Target = real.
- **Provenance-clean** — every pair traces to `source` + `eval_ref`.

## D. Lane `gap_cover_selection_v1` — teach CHOOSING, not inventorying

Gap: ep3 lists all available points instead of selecting the strongest + compressing. Train the
map **abundant evidence → tight shipped cover**. The user turn deliberately contains MORE evidence
than the cover uses, so the learned behavior is *selection under abundance*.

```json
{
  "messages": [
    {"role": "system",  "content": "<verbatim careers_kb cover instructions + voice/cannot-lie gate as injected in production>"},
    {"role": "user",    "content": "<job + research brief + FULL candidate evidence inventory (the whole superset of usable points — repos, metrics, background)>"},
    {"role": "assistant","content": "<the SHIPPED cover — the selected + compressed version that passed the blind judge>"}
  ],
  "meta": {
    "lane": "gap_cover_selection_v1",
    "frozen_regression": false,
    "provenance": {"source": "bundles/<id>", "eval_ref": "ep1_blind_row_<n>", "shipped": true, "verdict": "PASS", "word_count_in": 0, "word_count_out": 0},
    "selection_rationale": "<what was cut and why — AUDIT/EVAL METADATA ONLY, never trained (not in the assistant turn)>"
  }
}
```

Notes:
- **Do NOT put the selection rationale in the assistant turn** (it would train the model to emit
  meta-commentary). Keep "what was cut and why" as an optional top-level `selection_rationale`
  field — audit/eval metadata only, never trained.
- Prefer pairs where `word_count_in` >> `word_count_out` (genuine compression signal).
- A handful of **contrast pairs** welcome: same input, a bloated-inventory draft flagged in
  `provenance.negative:true` — tutor decides at D-verdict whether to use as DPO-style later
  (not in the first LoRA pass; SFT trains only the positive/shipped target).

## E. Lane `gap_ui_action_v1` — teach state → ONE correct primitive + verification

Gap: ep3 UI judgment (from ep2 replay misses). Train the map **observed state → the single next
primitive call**, with the verification observation that confirms it. One action then observe
(the act.py discipline).

```json
{
  "messages": [
    {"role": "system",  "content": "<taeys-hands primitive schema verbatim: tree_view (eyes) + act.click/act.type/act.do (hands); role+label+display args; discipline: ONE action then observe>"},
    {"role": "user",    "content": "<filtered AT-SPI interactive tree snapshot + the step goal + the prior action's result>"},
    {"role": "assistant","content": "act.click('Submit application', role='push button', display=':8')"}
  ],
  "meta": {
    "lane": "gap_ui_action_v1",
    "frozen_regression": false,
    "provenance": {"source": "recording/attempt-12", "eval_ref": "ep2_replay_action_<idx>", "was_miss": true, "correct_action": "<canonical form>"}
  }
}
```

Notes:
- Assistant turn = **exactly one** primitive call in the canonical `act.*` form (the production
  call shape), nothing else. If the duty also emits a verification step, model it as a SECOND
  pair (state-after → the observe/verify call), not two actions in one turn.
- **Prioritize the misses** (`was_miss:true`) — those are the measured gap. Include enough
  correct-action pairs from the same recording for context/balance (treasurer's call on ratio;
  flag it so tutor can weight).
- Targets MUST match a real recorded correct action (attempt-12 ground truth). No invented trees.

## F. Delivery + registration

- Treasurer writes each lane to `treasurer/foundations/careers/training_data/v2/pairs/` and
  registers it (id + sha + row count), same as existing lanes.
- Ping tutor per lane; tutor D-verdicts → appends a row to [[SFT_D_VERDICT_v1]] (PASS/HOLD +
  counts + remedy), then folds PASS lanes into the SFT module with a mixture weight.
- Re-eval is treasurer's frozen blind protocol, base-vs-module, after each round. Per-duty cutover
  only on PASS. Never train on a heldout row; never cut over on a self-report.
